# 视频 → 文字文档：最终流程方案

> 实测对象：`2026-09-26 17-04-56_大梁_Max_用Obsid_video.mp4`（27:29 / 1920×1080 / 127 MB）
> 结果：**7.4 分钟**出稿，覆盖全片 1649.3 秒；中断后重跑 **1 秒**补齐。
> 环境：Windows 11，20 核 CPU，15.6 GB 内存（可用约 8 GB）。

---

## 一句话

**把音轨整段交给语音模型，全自动产出带时间戳的逐字稿；画面只用来看一眼「这是什么形态的视频」。**

不要逐帧看图——视频里 95% 的信息在语音，抽帧既慢又不可能穷尽。

---

## 两种用法

### 方式一：双击 bat（不需要 AI，也不需要敲命令）

`~/.workbuddy/skills/video-to-text-notes/scripts/视频转文字.bat`

- **把视频文件拖到 bat 图标上松开** → 自动出逐字稿
- 输出到**视频同目录的 `逐字稿/` 文件夹**
- 中间产物放视频同目录 `.asr_work/`（同一视频重跑**秒级复用**，删掉也不影响）
- 实测：27 分钟视频首次 7.4 分钟；中断后重跑 3.7 分钟补齐

> 这个 bat 里没有任何 AI 调用，ffmpeg + whisper 模型全在你机器上跑，断网也能用。

### 方式二：命令行（给 AI / 批处理调用）

```bash
PY="<项目虚拟环境>/Scripts/python.exe"
"$PY" -u "<video-to-text-notes 技能目录>/scripts/video_to_notes.py" \
      "<视频绝对路径>" --work "<项目>/build_tmp/asr" --out "<项目>/docs/video-notes" \
      --prompt "<一句话交代主题与专有名词>" \
      --fix "workbody=WorkBuddy,DeepSake=DeepSeek"
```

跑完就得到两份文件：

| 文件 | 内容 |
| --- | --- |
| `<视频名>-逐字稿.md` | 带 `[分:秒]` 时间戳，按停顿/句末标点分段 |
| `<视频名>-transcript.json` | 机器可读，供后续写结构化笔记 |

> ⚠️ **必须前台跑完**（把 timeout 放到 15 分钟）。非交互模式下回合结束会杀掉子进程。
> 但即使被杀也不亏：已完成的片有 `.done` 标记，重跑同一条命令会**自动跳过**。

## 内部五步

| 步 | 做什么 | 关键点 |
| --- | --- | --- |
| 1 探形 | ffprobe 拿时长/分辨率/音轨 | 无音轨 → 直接报错并提示改走 OCR 路线，不浪费你时间 |
| 2 抽音频 | ffmpeg → 16 kHz 单声道 PCM wav | 27.5 min ≈ 50 MB |
| 3 分片 | 检测静音 → 等分切点**吸附到静音中心** | 前后各扩 0.6 s 缓冲，合并时按核心区间裁掉重叠。**避免把句子切成两半** |
| 4 转写 | 多进程并行，每进程独立加载模型 | 每片独立落盘 + `.done` 标记；单片失败不炸全局 |
| 5 合并 | 按绝对时间排序、去重、应用校正词表 | 输出 md + json |

| --- | --- | --- | --- | --- |
| 串行（旧，1.9x 实时） | ~15 分钟 | 865 | 10800 | 0 → 1648.9 s |

## 参数速查

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--jobs N` | 按 CPU + 可用内存自动 | 并发进程数。本机自动取 5 |
| `--chunks N` | `jobs × 2` | 切片总数。切细一点利于负载均衡，**不影响峰值内存** |
| `--out dir` | `<cwd>/docs/video-notes` | 输出目录 |
| `--work dir` | `<cwd>/build_tmp/asr` | 中间产物。**每处理一个新视频换一个目录** |
| `--model` | `small` | `base` 更快更糙 / `medium` 更准更慢（内存也更大） |
| `--prompt` | 通用中文 | **交代主题与专有名词，能显著减少同音错字，强烈建议传** |
| `--fix` | 空 | 专有名词校正，形如 `错=对,错2=对2` |
| `--force` | 关 | 丢弃切片与结果从头重来 |

## 四个关键设计（都是踩坑换来的）

**1. 切点必须选在静音中心。**
等分切点会落在句子中间，导致边界词被截断或重复。脚本先用 `silencedetect` 找出静音区间，把每个等分点吸附到 ±60 s 内最近的静音中心。

**2. 并发度由「可用内存」决定，不是 CPU 核数。**
每个 whisper int8 子进程峰值约 1.2~1.5 GB。本机 20 核但只有 8 GB 可用内存——**8 进程直接 `mkl_malloc: failed to allocate memory`**。
另一个隐形杀手：子进程各自开满「CPU 核数」个 BLAS 线程，内存与调度双双爆炸。所以子进程启动时**必须先限制** `OMP_NUM_THREADS` / `MKL_NUM_THREADS`（必须在 import ctranslate2 之前）。

**3. 切片方案要留指纹。**
切片目录里写一份 `plan.json`（片数 + 总时长）。复用前校验：方案不一致就**整体重切**。
—— 踩过的坑：按 8 片切好的目录被当成 6 片复用，结果只转了前 6 片，**音频尾部 370 秒静默丢失**（还看不出来，因为没有任何报错）。

**4. 失败要隔离，不要炸全局。**
单片转写失败只记一笔，其余继续；如果是内存类错误，**自动把并发减半后重试失败的片**。最终还会校验「转写终点 vs 视频时长」，差超过 60 秒就告警。

## 排障表（9 个坑，全部实测踩过）

| # | 症状 | 根因 | 解法 |
| --- | --- | --- | --- |
| 1 | pip 报 `(from versions: none)`，但源页面 curl 是 200 | 本机**系统代理**干扰镜像源 | 换 **官方源 pypi.org**；先 `env \| grep -i proxy` |
| 2 | `model.bin is incomplete` | Windows 建符号链接失败，`snapshots/` 下全是 0 字节 | **脚本已自动修复**：读 `trees/*.json` 从 `blobs/` 硬链接重建本地模型目录 |
| 3 | `open() got an unexpected keyword argument 'metadata_errors'` | faster-whisper 1.2.1 与 **av 19** 不兼容 | **脚本已绕开**：ffmpeg 转 wav + `wave` 读 numpy 直喂模型 |
| 4 | 后台任务跑到一半突然没了 | 非交互模式**回合结束即杀后台子进程** | 前台跑完；或依赖 `.done` 标记续跑 |
| 5 | 中间产物凭空消失 | **系统清理 `%TEMP%`** | 中间产物一律放项目内 `build_tmp/` |
| 6 | `mkl_malloc: failed to allocate memory` | 并发进程数 × 每进程内存 > 可用内存 | **脚本已自动降级**：并发减半重试 |
| 7 | 逐字稿缺尾巴，且无任何报错 | 切片元数据与转写结果**同名互相覆盖**；复用时不校验切片方案 | 元数据改用 `.meta.json`；`plan.json` 校验方案指纹 |
| 8 | 装语音库后项目依赖被搞坏 | pip 把 `click` 8.1.7 升到 8.5.0，而 **f2 硬依赖 8.1.7** | 装完 `pip list` 扫一眼，手动降回 |
| 9 | 双击 bat，中文提示全乱码 | bat 存成 UTF-8 / 留着 `chcp 65001` / 用了 LF 换行 —— **cmd 按系统代码页(936)解析 bat 文件**，不是按控制台代码页 | 跑 `python scripts/fix_bat_encoding.py`（GBK + CRLF + 去 chcp）。**诊断陷阱**：PowerShell 的 `*>` 重定向会写成 UTF-16LE，字符间夹 `\x00`，看着也像乱码，别误判 |

## 已知限制与优化方向

- **瓶颈是内存，不是 CPU**。本机 20 核只能开 5 并发。内存加到 32 GB 可开到 11+ 并发，预计压到 **3~4 分钟**。
- 想更快可以换 `--model base`（速度约翻倍，专有名词错误率上升）。
- 单进程 4 线程约 0.96x 实时；ctranslate2 的多线程效率**不随线程数线性增长**（20 线程也只有 1.9x），所以「多进程 + 少线程」优于「少进程 + 多线程」。
- 脚本产出的是 **ASR 初稿**。正式交付前建议通读一遍，用 `--fix` 补专有名词校正；结构化笔记仍需人来提炼。
- 画面线（章节骨架）目前是**独立步骤**，没有并入脚本。若视频是 PPT / 分章讲解类，可另跑抽帧检测标题页。
