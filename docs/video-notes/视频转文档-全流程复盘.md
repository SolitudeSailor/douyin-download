## 阶段 1 · 探明形态（**最关键的一步**）

用 OpenCV 读元信息：

```
fps=30.0   frames=49482   1920×1080   时长 1649.4s（27 分 29 秒）
```

均匀抽 24 帧肉眼确认，得到形态判断：

- **横屏 + 长时长 + 口播 + 底部硬字幕** → 典型的录屏教程
- ✅ **决策：语音是内容主体，走"音频转写为主 + 关键帧定骨架"的路线**
- ❌ **否决：逐帧看图**（无法穷尽，且人脸/PPT 帧信息密度远低于语音）

> 这一步定错了，后面全白干。所以第一件事永远是"花 30 秒看清视频长什么样"。

| 动作 | 结果 |

| 装 faster-whisper 1.2.1 | 连带 av 19.0.0 / ctranslate2 4.8.2 / onnxruntime 1.30 / tokenizers 0.23 |
| 拉 small 模型 | 484 MB → `.workbuddy/cache/whisper/small-local` |

**踩坑 1（pip）**：本机有系统代理 `http_proxy=127.0.0.1:11579`，走清华源 pip 报
`(from versions: none)`（源页面 curl 明明 200）→ 换**官方源 pypi.org** 立刻成功。

**副作用修复**：pip 顺手把 `click` 从 **8.1.7 升到 8.5.0**，而本项目 **f2 硬依赖 `click==8.1.7`**
→ 手动降回，保住了抖音下载器。

## 阶段 3 · 抓章节骨架（画面侧）

思路：**章节标题页 = 大面积荧光黄/紫色块**。

- 每 2 秒抽 1 帧（825 帧），缩到 320×180 做像素比例统计
- 黄色/紫色占比 >4% 判为标题页 → 91 个原始命中
- 相邻 <6 秒聚为一簇 → **24 个章节页**
- 多模态读图 → 拿到全片骨架：*新建仓库 → 搭建文件系统 → 知识系统 → 收藏视频 → 存储本地文件 → 思考/咀嚼/拆分/记录 → 知识库管理 → 定时任务自动化 → 结尾升华*

> 只花了 24 帧就读完了 27 分钟的"目录页"，这是画面唯一需要出力的地方。

## 阶段 4 · 语音转写（内容主体）

```
ffmpeg -i video.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le audio.wav   → 52.8 MB
```

模型跑 CPU `int8` + `small` + `beam_size=5` + VAD，速度 **≈1.9x 实时**。

**三次中断，三种原因，三种解法**：

| # | 症状 | 根因 | 解法 |
| --- | --- | --- | --- |
| 1 | `model.bin is incomplete: failed to read a value of size 4` | Windows **建符号链接失败**，`snapshots/` 下全是 **0 字节**空文件（`blobs/` 里是好的） | 读 `trees/<sha>.json` 拿映射（LFS 文件 blob 名是 `lfs_sha256`），把真实文件硬链接成 `model.bin` 等四件套到 `small-local/`，直接把该目录喂给 `WhisperModel()` |
| 2 | `TypeError: open() got an unexpected keyword argument 'metadata_errors'` | faster-whisper 1.2.1 与 **av 19** API 不兼容 | **绕开 av**：用标准库 `wave` 读 16k wav 成 numpy float32，直接喂 `transcribe(audio_array)` |
| 3 | 跑到 83.6% 突然没了（两次） | ① 中间产物放 `%TEMP%` 被**系统清掉**；② **回合结束即杀后台子进程** | ① 中间产物移入项目内 `build_tmp/vidx/`；② 长任务**前台跑**，并做**断点续跑**（从"已覆盖时间 −5s"切剩余音频重转，按时间戳合并去重） |

**断点续跑的收益**：剩下 276 秒音频只补跑 **110 秒**，而不是把 27 分钟重来一遍。

**最终**：865 段、10,800 字、覆盖 0 → 1643.9 秒（全片 1649 秒，尾部静音未出文本）。

## 如果重来一次（可优化项）

1. **分片并行**：把音频切成 N 段多进程同时转写（本机多核），27.5 分钟音频可从 15 分钟压到 **3～5 分钟**。本次没做。
2. **一开始就按"断点续跑"设计**：先写增量落盘 + 从已覆盖点续跑的逻辑，就不会有两次全丢。
3. **一开始就绕开 av**：直接用 ffmpeg + numpy 通道，省掉一次踩坑往返。
4. **专有名词先喂进 `initial_prompt`**：能进一步降低同音错字率。
